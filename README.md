# SAP SM: XLSX → Incident (Выполненные работы)

![Tampermonkey](https://img.shields.io/badge/Tampermonkey-Userscript-green)
![SAP Solution Manager](https://img.shields.io/badge/SAP-Solution%20Manager-blue)
![License](https://img.shields.io/badge/License-MIT-lightgrey)

Userscript (Tampermonkey) для автоматического переноса строк из Excel-файла (лист «Выполненные работы») в SAP Solution Manager (CRM WebClient UI) в качестве инцидентов `AIC_OB_INCIDENT`.

Скрипт полностью автоматизирует рутину: заполняет заголовок, настраивает партнеров, выбирает категории и статусы, добавляет длинные тексты (описание и решение) и сохраняет инциденты.

## 🚀 Основные возможности

- **Полная автоматизация:** Проходит путь от нажатия «Создать сообщение» до сохранения готового инцидента со статусом «5. Предложение по решению».
- **Устойчивость к динамическим ID:** SAP генерирует префиксы ID (например, `C32_W39...`) при каждой перезагрузке. Скрипт умеет находить элементы, отбрасывая динамическую часть префикса.
- **Умные ожидания:** Использует DOM-маркеры и перехват сетевых запросов (`XMLHttpRequest`), чтобы дожидаться полной загрузки фреймов и ответов сервера. Никаких «глухих» задержек.
- **Контроль выполнения:**
  - **⏹ Стоп (Мягкий):** Завершает текущую строку (сохраняет инцидент) и останавливает процесс.
  - **✖ Прервать (Жесткий):** Мгновенно останавливает скрипт.
  - **Пауза/Продолжить:** Позволяет приостановить работу, не сбивая прогресс.
- **Сохранение прогресса:** Запоминает последнюю успешно обработанную строку в `LocalStorage`. При повторном запуске предложит продолжить с нужного места.
- **Режим отладки:** Встроенный лог с точностью до миллисекунд и режим «пошагового» выполнения для детальной проверки.

## 📋 Требования

1. Браузер на базе Chromium (Edge, Chrome, Яндекс.Браузер) или Firefox.
2. Установленное расширение [Tampermonkey](https://www.tampermonkey.net/).
3. Доступ к SAP Solution Manager (домены `sapsm3.sap.metinvest.com` или `sapsm3ci.sap.metinvest.com`).

## 🔧 Установка

1. Убедитесь, что у вас установлен Tampermonkey.
2. Перейдите по ссылке на raw-версию скрипта:
   👉 **[Установить скрипт (raw)](https://raw.githubusercontent.com/emz13666/SAP_SM_from_xlsx/main/sap-sm-from-xlsx.user.js)**
3. Tampermonkey предложит установить скрипт. Нажмите **«Установить»**.
4. Скрипт автоматически будет обновляться при выходе новых версий.

## 📊 Формат Excel-файла

Скрипт читает **только** лист с названием `Выполненные работы`. 
Ожидается следующая структура колонок (индексация с 0):

| Колонка | Индекс | Содержимое |
|---------|--------|------------|
| A | 0 | Дата (формат `ДД.ММ.ГГГГ`) |
| B | 1 | Время приёма |
| C | 2 | (Не используется в тексте) |
| D | 3 | Дата окончания |
| E | 4 | Категория |
| F | 5 | Объект (Оборудование) |
| G | 6 | Неисправность |
| H | 7 | Выполненные работы (Решение) |
| I | 8 | Категория SAP (формат `"Текст - 1.11"`) |
| J | 9 | Система (влияет на выбор Группы поддержки) |
| K | 10 | Исполнитель |

*Из колонки **I** скрипт извлекает номер (например, `1.11`), чтобы проставить нужные подкатегории.*
*Колонка **J** проверяется на наличие систем: `Modular`, `КОБУС`, `Серверное оборудование`, `Серверное программное обеспечение`. Если совпадение найдено — выбирается группа «MODULAR», иначе — «LGOK-Telekom».*

## 🖥️ Использование

1. Откройте SAP Solution Manager и авторизуйтесь.
2. В правом верхнем углу появится панель скрипта `SAP SM: XLSX → Incident`.
3. Нажмите на поле выбора файла и укажите ваш `.xlsx` файл.
4. Скрипт прочитает файл и предложит строку, с которой нужно начать (на основе сохраненного прогресса или первой строки).
5. Нажмите **«▶ Старт»**.
6. *Рекомендация:* При первом запуске включите галочку **«ДЕТАЛЬНАЯ ОТЛАДКА»** и **«пошагово»**, чтобы убедиться, что все поля заполняются корректно.

## ⚠️ Важные нюансы

- **Не открывайте DevTools (F12) во время работы скрипта.** Изменение размера окна (viewport) заставляет SAP перерисовывать фреймы (срабатывает ResizeHandler), из-за чего форма может «улететь» на главную страницу или потерять введенные данные.
- **Логика ожидания:** Скрипт намеренно использует сложные проверки готовности DOM и ожидания сетевых запросов (хук на `XMLHttpRequest`), чтобы избежать ошибок при медленном соединении с SAP.
- **Сброс прогресса:** Если нужно начать заново, просто измените номер строки в поле «Начать со строки» вручную.

## 🛠 Технические детали (для разработчиков)

Скрипт написан на чистом JavaScript (ES6+) без использования сторонних библиотек, кроме `xlsx` (подключается через `@require`).
- Поиск элементов осуществляется функцией `findInFrames()`, которая рекурсивно обходит все `iframe` и использует регулярные выражения для поиска по суффиксу ID.
- Для эмуляции кликов используются `realClick` (MouseEvent) и `nativeSubmitButton` (вызов нативных функций SAP `htmlbSubmitLib` и `htmlbSL`).
- Вызов дропдаунов SAP (не `<select>`, а `readonly input`) реализован через клик по кнопке, ожидание появления пункта в DOM и клик по тегу `<a>`.
